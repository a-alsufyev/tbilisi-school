# Архитектура Tbilisi Schools

Каталог школ Тбилиси: главная страница, карта, карточки школ, справочник программ, международных статусов и аккредитаций, интерфейс на четырёх языках (EN, RU, GE, DE).

Приложение — React-клиент и Express-сервер. В рантайме источник данных — **PostgreSQL**. CSV, TXT и JSON в `data/` остаются в git как сид и бэкап контента; запросы API их не читают.

Подбор школ в диалоге идёт через OpenAI на сервере (`POST /api/assistant`). Ключ в браузер не отдаётся. Переводы интерфейса — в `src/i18n/index.ts`, имена школ — в таблице `school_translations`.

Связанные документы: [change-plan.md](./change-plan.md), [implementation-checklist.md](./implementation-checklist.md), выкладка на VPS — [production.md](./production.md), ассистент — [assistant.md](./assistant.md), заготовка авторизации — [schema-next.md](./schema-next.md).

## Общая схема

```
Браузер
  ├── React UI + react-router-dom
  ├── i18next (язык из :lang в URL)
  └── Yandex Maps JS API
        │
        │  GET /api/schools
        │  GET /api/schools/:slug/description
        │  GET /api/directory
        │  GET /api/config
        │  GET|POST /api/visits
        │  POST /api/assistant
        ▼
Express (`server.ts`)
  ├── Vite middleware (dev) или статика dist/ (production)
  └── Drizzle → PostgreSQL
        ▲
        │  только если в schools 0 строк
        │
data/schools.csv
data/descriptions/*.txt
data/school-names.json
```

При старте приложения: миграции → сид, если таблица школ пустая → listen. На VPS перед этим пустой volume Postgres один раз восстанавливает дамп текущей базы.

## URL

`lang` ∈ `en | ru | ge | de`. Школа в пути — латинский kebab-case slug, не числовой id и не старые файловые ключи вроде `северная_школа`.

```
/                              → /{lang} по языку браузера, если en|ru|ge|de, иначе /en
/{lang}                        главная
/{lang}/map                    карта на весь экран
/{lang}/schools                каталог
/{lang}/schools/{slug}         карточка школы
/{lang}/directory              справочник используемых программ, статусов и аккредитаций
/{lang}/assistant              диалог подбора школы
/{lang}/about                  о проекте
/{lang}/login
/{lang}/register               404 (пути зарезервированы, страниц входа нет)
/{lang}/account
```

Каталог читает необязательный query: `q`, `lang`, `program`, `intl`, `district`. Смысл параметров — в разделе «Главная» ниже.

Невалидный `lang` → редирект на `/en` + тот же хвост пути. Неизвестный slug → 404 в SPA, URL каталогом не подменяется. Смена языка в шапке меняет только префикс и сохраняет query-строку.

Кнопка возврата на карточке школы не ходит по истории браузера. Ссылка из каталога, с карты и из ассистента несёт `?from=catalog`, `?from=map` или `?from=assistant`. Кнопка ведёт в каталог, на `/{lang}/map` или к ассистенту уже на текущем языке. Прямой заход без `from` ведёт в каталог. Карточка с главной тоже использует `?from=catalog`.

Навигация в `Header` — `<NavLink>`: Главная, Карта, Каталог, Справочник, AI-ассистент, О проекте. Логотип ведёт на главную. Подпись пункта диалога на EN — AI Assistant, на GE — AI-ასისტენტი, на DE — AI-Assistent.

## Данные

### Рантайм — Postgres

Схема: `src/db/schema.ts`. Таблиц `users` и `comments` в этой волне нет.

**schools**

- `id` UUID PK
- `slug` TEXT UNIQUE NOT NULL
- `address` TEXT
- `lat` / `lng` DOUBLE PRECISION NULL
- `languages` TEXT NOT NULL — через запятую: код `RU` или `EN` и пара `bilingual:RU/EN`. У школы может быть несколько пунктов сразу
- `website` TEXT NULL
- `cost` TEXT NULL — прежняя свободная строка, после переноса пустая
- `cost_min` / `cost_max` DOUBLE PRECISION NULL
- `cost_currency` TEXT NULL — `USD`, `EUR` или `GEL`
- `cost_status` TEXT NOT NULL DEFAULT `approximate` — `official`, `approximate` или `unknown`. При `unknown` сумма, валюта, период и год пустые
- `cost_year` INTEGER NULL — год, на который указана цена, с 2022
- `cost_period` TEXT NULL — `month` или `year`
- `name_locale` TEXT NOT NULL DEFAULT `en` — какое из четырёх имён основное: `en`, `ru`, `ge` или `de`
- `created_at` / `updated_at`

**school_translations**

- `school_id` FK → schools (PK вместе с `locale`)
- `locale` TEXT — `en` | `ru` | `ge` | `de`
- `name` TEXT NOT NULL
- `description` TEXT NOT NULL DEFAULT ''

**lookup_items**

Три справочника каталога. Страница `/{lang}/directory` читает только те пункты, которые выбраны хотя бы у одной школы. Это не вход на сайт из [schema-next.md](./schema-next.md).

| `kind` | Подпись в админке и по-русски | en | ge | de |
|---|---|---|---|---|
| `program` | Программа | Program | პროგრამა | Programm |
| `international_status` | Международный статус | International status | საერთაშორისო სტატუსი | Internationaler Status |
| `accreditation` | Аккредитация | Accreditation | აკრედიტაცია | Akkreditierung |

- `id` UUID PK
- `kind` TEXT NOT NULL — одно из трёх значений таблицы
- `label` TEXT NOT NULL — одна подпись на все языки сайта, до 120 символов
- `created_at` / `updated_at`
- уникальность `(kind, lower(label))`

**school_lookup_items**

- `school_id` FK → schools, каскад при удалении школы
- `item_id` FK → lookup_items, удалить пункт нельзя, пока он выбран у школы
- первичный ключ — пара этих колонок

У школы в каждом справочнике может быть несколько пунктов. Старая колонка `schools.program` снята: миграция перенесла непустые строки в справочник программ, склеив одинаковые подписи без учёта регистра. «US Curriculum» и «American» остались разными пунктами. Международный статус и аккредитация после миграции пустые.

**site_stats**

- `key` TEXT PK — сейчас `visits`
- `value` INTEGER NOT NULL DEFAULT 0

Правки контента на заполненной БД — в Postgres (или повторный сид после очистки таблиц школ). Файлы в `data/` сами по себе API не меняют. В админке (`/admin`) два раздела: школы и справочники. Основное имя выбирается радиокнопкой напротив одного из четырёх написаний. Языки обучения — несколько отметок сразу, включая билингвальные пары. Цена задаётся статусом «официальная / ориентировочная / нет информации», границами «от» и «до», валютой (USD, EUR, GEL), периодом (месяц или год) и необязательным годом. При «нет информации» сумма, валюта, период и год недоступны и в базе сохраняются пустыми. У существующих школ основное имя по умолчанию английское; пустая цена стала `unknown`, остальные цены — `approximate`.

В справочниках администратор добавляет, переименовывает и удаляет значения программ, международного статуса и аккредитации. Подпись — до 120 символов, без дубля в том же справочнике без учёта регистра. Удаление занятого пункта не проходит. В карточке школы каждый справочник — набор галочек. На публичной карточке вместо одного поля «Программа» три поля; пустой список показывается как «—». Подписи полей переводятся, сами значения — нет. В сетке каталога вместо полного перечисления стоят бейджи языков, программ и подтверждённого международного статуса. Балун карты эти поля не показывает.

### Сид — файлы

Если при старте в `schools` 0 строк, сид читает:

| Файл | Назначение |
|---|---|
| `data/schools.csv` | Адрес, координаты, языки, стоимость, программа (в справочник программ) |
| `data/descriptions/{file-slug}.txt` | Описание (матч по старому файловому ключу) |
| `data/school-names.json` | Имена `en` / `ru` / `ge` / `de` |
| `src/i18n/index.ts` | Строки UI (не сид БД) |

В БД пишется латинский URL-slug (`newton-free-school`, `northern-school`, `intellect-plus`). Колонка `program` из CSV становится пунктами справочника программ и связями со школами; одинаковые подписи без учёта регистра склеиваются. Повторный старт при непустой таблице строки не дублирует.

На VPS этот сид не заполняет первую базу: init-скрипт Postgres сначала восстанавливает `deploy/tbilisi.dump`. Сид из CSV остаётся запасным путём и срабатывает только если приложение стартовало, таблица школ пустая, а restore уже не выполнялся.

Парсер CSV: `src/db/parse-csv.ts`, вызывается только из `src/db/seed.ts`.

## Клиент

Точка входа: `src/main.tsx` (`BrowserRouter`) → `src/App.tsx`.

Список школ и ключ Яндекса загружаются один раз (`GET /api/schools`, `GET /api/config`). Описание — при открытии карточки по латинскому slug. Имена приходят в поле `names` ответа API (`useSchoolTranslations`), не из бандла `school-names.json`.

Чёрным показывается основное имя: `names[nameLocale]`. Серым — перевод на язык страницы, и только если он непустой и отличается от основного. В выдаче ассистента серой строки нет: и карточки, и заголовки сравнения используют основное имя. Цена на карточке и у ассистента остаётся в валюте каталога. Под суммой — статус и, если задан, год; период пишется у самой суммы. «Нет информации» год и период не показывает.

На странице школы три поля из справочников: программа, международный статус, аккредитация. Несколько подписей пишутся через запятую, по алфавиту. Пустой список — «—». Название поля берётся из языка страницы, текст значения остаётся тем, что ввёл администратор. У ассистента те же три списка стоят на карточке подбора и в таблице сравнения. В балуне карты этих полей нет.

Сетка каталога и блок «Избранные» на главной используют одну карточку (`src/components/SchoolCard.tsx`). На ней бейджи (`src/components/SchoolBadges.tsx`): коды языков обучения, до двух программ и «+N», подтверждённый международный статус со звёздочкой. Подписи «International status not verified» и «No confirmed international status» бейджем не становятся (`confirmedInternationalStatuses` в `src/lib/lookups.ts`). Они остаются в полях страницы школы и в справочнике. Статус «Other», если он записан как международный, бейджем показывается.

Обложка карточки и шапка страницы школы — `src/components/CoverImage.tsx`. Без файла это градиент по хэшу и инициалы названия. Свой кадр кладётся в `public/` и подхватывается без правки кода:

- `public/schools/<slug>.jpg` — обложка этой школы;
- `public/districts/<id>.jpg` — фото района; для школы без своего файла это запасной кадр.

Идентификаторы районов: `saburtalo`, `vake`, `mtatsminda`, `krtsanisi`, `isani`, `samgori`, `chughureti`, `didube`, `nadzaladevi`, `gldani`. Район школы считается по координатам (`src/lib/districts.ts`), не из текстового поля. Нет файла — один запрос за загрузку страницы, дальше остаётся градиент. Другие расширения, кроме `.jpg`, код не ищет.

На странице школы слева от карты Яндекса — схема десяти районов (`src/components/DistrictMiniMap.tsx`): район школы подсвечен, точка стоит на её координатах. Та же проекция на главной (`src/lib/city-scheme.ts`): точки всех школ, клик по району открывает каталог с `?district=`.

### Главная

`/{lang}` — `src/pages/HomePage.tsx`, не карта. Карта на весь экран — `/{lang}/map`.

Сверху поле с двумя режимами. «AI-подбор» записывает текст в черновик диалога, отправляет его и открывает `/{lang}/assistant`. Примеры под полем делают то же сразу. «По названию» открывает каталог с `?q=`. Справа на широком экране — схема районов. Ниже: полоса чисел (школы, языки обучения, программы, школы с известной ценой), чипы языков и шести частых программ, карта уменьшенной высоты со ссылкой на полную карту, плитки районов, подборки (международные, англоязычные, русскоязычные, грузиноязычные), блок ассистента, шесть карточек с наибольшим числом подтверждённых международных статусов, ссылки на справочник и «О проекте». Скрипт Яндекса на главной грузится, когда блок карты попадает в зону прокрутки.

Ссылки в каталог собирает `src/lib/home.ts`. Query, все необязательные:

| Параметр | Смысл |
|---|---|
| `q` | Подстрока в имени, переводе имени и адресе |
| `lang` | Код языка обучения: `EN`, `RU`, `GE`, `DE`, `FR` |
| `program` | Точное совпадение с подписью программы |
| `intl` | `1` — есть подтверждённый международный статус |
| `district` | Идентификатор района, район по координатам школы |

Над списком каталога видны активные условия и сброс. Без query список полный. Подборка «Международные» и `intl=1` не считают две служебные подписи статуса.

### Справочник

Страница `/{lang}/directory` объясняет пункты тех же трёх справочников. Старые темы про типы школ, языки, поступление и шесть фиксированных программ с неё сняты. Страница запрашивает `GET /api/directory`. Раздел без пунктов не показывается.

Ответ — `{ program, international_status, accreditation }`, в каждом массиве объекты `{ label }`. Пункт попадает туда, только если выбран хотя бы у одной школы. Идентификаторы, число школ и неиспользуемые подписи не отдаются. Сессия не нужна.

Заголовок карточки — подпись из базы, без перевода, как на карточке школы. Текст берётся из `src/content/directory.ts`: ключ — вид и подпись без учёта регистра, абзац на `en`, `ru`, `ge` и `de`. Описания в `lookup_items` не хранятся. Если заготовленного текста нет, карточка всё равно видна, с фразой на языке страницы, что описание готовится. Переименование подписи в админке отвязывает текст, пока ключ в этом файле не совпадёт с новой подписью.

Содержательные пункты рисуются карточками с обложкой, как школы: градиент, инициалы, метка раздела. У программы внизу ссылка в каталог с `?program=` и этой подписью. Служебные отметки (`marker` в том же файле: «Other», «Not identified», «No confirmed…», «not verified») идут ниже, пунктирной карточкой без обложки, под заголовком «Пометки». Сначала содержательные, затем отметки; внутри группы подписи сортируются по алфавиту языка страницы, для грузинского сравнение идёт как `ka`. Похожие подписи не склеиваются: British, Cambridge и Pearson Edexcel — разные карточки, программа Cambridge и статус Cambridge International School — тоже.

Под заголовком страницы закреплена строка поиска по названию и тексту статьи и чипы разделов. Число на чипе — сколько пунктов в разделе всего, не сколько осталось после поиска. Ошибка загрузки или ответ не той формы показывает сообщение об ошибке. Три пустых списка — отдельная фраза, что ни один пункт пока не используется. Пока ответ не пришёл, на месте карточек скелетоны.

В балунах карты HTML экранируется (`src/lib/escapeHtml.ts`). Клик по школе на полной карте и на карте главной ведёт на `/{lang}/schools/{slug}?from=map`.

## Сервер

`server.ts` слушает `PORT` (по умолчанию 3000) на `0.0.0.0`. Сначала `prepareDatabase()`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Проверка живости |
| GET | `/api/schools` | Список из БД: `slug`, координаты, поля карточки, `nameLocale`, `costStatus`, `programs`, `internationalStatuses`, `accreditations` (массивы подписей), `names: { en, ru, ge, de }` (без описаний) |
| GET | `/api/directory` | Используемые пункты справочников: `{ program, international_status, accreditation }`, в каждом массив `{ label }`. Без сессии, без числа школ и без неиспользуемых пунктов |
| GET | `/api/admin/lookups` | Справочники: `id`, `kind`, `label`, `schoolCount`. Только с сессией администратора |
| POST | `/api/admin/lookups` | Новый пункт `{ kind, label }` |
| PATCH | `/api/admin/lookups/:id` | Новая подпись |
| DELETE | `/api/admin/lookups/:id` | Удаление; 409, если пункт выбран у школы |
| GET | `/api/schools/:slug/description` | Текст описания; query `locale` |
| GET | `/api/config` | Ключ Yandex Maps |
| GET | `/api/visits` | Текущее число посещений |
| POST | `/api/visits` | +1 в `site_stats`, вернуть новое значение |
| POST | `/api/assistant` | Диалог подбора: тело `{ locale, messages }`, ответ `{ reply, schools, comparison }` |

Создание и правка школы (`POST` и `PUT /api/admin/schools`) принимают `programIds`, `internationalStatusIds` и `accreditationIds`: массивы id из нужного справочника. Пустой массив снимает все отметки этого справочника.

Slug: только `[a-z0-9-]+` (кириллица и `../` → 400). Неизвестная школа → 404.

Режимы:

- `npm run dev` — не production, Vite middleware;
- `npm run build` затем `npm start` — статика из `dist/`, SPA fallback на `index.html`.

## Счётчик посещений

Клиент (`Footer.tsx`) один раз за вкладку вызывает `POST /api/visits` и ставит флаг в `sessionStorage`. Обновление страницы идёт через `GET` и не увеличивает число.

Сервер пишет в `site_stats` (`key = visits`) атомарно в SQL. IP не сохраняются. Файл `stats.json` не используется.

## Внешние сервисы

Обязательная внешняя зависимость в UI — **Yandex Maps**. Ключ: `YANDEX_MAPS_API_KEY` в `.env`, клиенту отдаётся через `/api/config`. В кабинете Яндекса ключ нужно ограничить боевым доменом.

Ассистент на `/{lang}/assistant` опционален. `OPENAI_API_KEY` остаётся на сервере. Модель по умолчанию `gpt-4o-mini` (`OPENAI_MODEL`). Без ключа `POST /api/assistant` отвечает 503. Сравнение цен в разных валютах для ответов ассистента идёт через курс Национального банка Грузии, без ключа. На карточках школ цена в другую валюту не пересчитывается.

Postgres — локально на Windows или контейнер `db` на VPS.

## Локализация

Языки: английский, русский, грузинский (`ge`), немецкий. Источник истины для UI — префикс URL. Запасной язык — английский.

Описания школ в сиде — на языке оригинала из `.txt`; в рантайме отдаётся запись перевода (пока один и тот же текст на все локали).

## Безопасность

- секреты не попадают в клиентский бандл, кроме ключа Яндекса;
- slug API ограничен латинским алфавитом с дефисом;
- `.env` не коммитится;
- GET API не пишет файлы на диск.

## Локальный запуск (Windows, без Docker)

Docker Desktop не нужен. `Dockerfile` / `docker-compose.yml` на этой машине не запускаем.

1. Установить PostgreSQL 16 на хост (например `winget install --id PostgreSQL.PostgreSQL.16`).
2. Создать роль и БД, совпадающие с `.env` (`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`).
3. Скопировать `.env.example` в `.env`. Заполнить `YANDEX_MAPS_API_KEY`. Локальный `DATABASE_URL` — хост **`127.0.0.1`**, не `localhost` (на Windows `localhost` может резолвиться в IPv6 `::1` и соединение падает). Пример:

   `DATABASE_URL=postgres://tbilisi:change_me@127.0.0.1:5432/tbilisi`

4. `npm install`
5. Разработка: `npm run dev` — сайт на http://localhost:3000. Миграции и сид (если школ 0) выполняются сами.
6. Продакшен локально: `npm run build` затем `npm start`.

Ручные команды (не обязательны, если уже вызван `dev` / `start`):

```bash
npm run db:migrate
npm run db:seed
```

Переменные — как в `.env.example`: `YANDEX_MAPS_API_KEY`, `PORT`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `DATABASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`.

## Ассистент

Страница `/{lang}/assistant`. Клиент отправляет историю диалога на `POST /api/assistant` (не больше 12 сообщений, история в базе не хранится). Модель вызывает инструмент `search_schools`, а сервер сам фильтрует каталог. С главной тот же диалог можно начать сразу: режим «AI-подбор» и примеры подставляют текст, отправляют его и открывают эту страницу. Подробности — в [assistant.md](./assistant.md).

## VPS

Файлы `Dockerfile`, `docker-compose.yml` и `deploy/restore.sh` гоняют **только на Ubuntu VPS**, после закрытия локальных этапов L0–L5. Локально Compose не используем.

Состав: `db` (`postgres:16-alpine`, volume `pgdata`) и `app`. Порт Postgres на хост не публикуется, снаружи его не открывать. Сайт слушает HTTP на порту 3000. `app` стартует после healthy `db`. В Compose `DATABASE_URL` указывает на хост `db` и перекрывает значение из `.env`.

Пароль `POSTGRES_PASSWORD` не должен содержать `@`, `:`, `/` и пробелы: Compose подставляет его в `DATABASE_URL` как есть.

### Что происходит при первом пустом volume

Entrypoint Postgres один раз выполняет `deploy/restore.sh`. Скрипт восстанавливает `deploy/tbilisi.dump` (`pg_restore --no-owner --no-acl --exit-on-error`): схема, школы, переводы, визиты и журнал drizzle. Затем приложение прогоняет миграции (уже записанные в дампе не переигрываются), видит непустую таблицу школ и сид из CSV пропускает.

Если дампа нет или `pg_restore` падает, скрипт очищает каталог данных и контейнер `db` завершается с ошибкой. Приложение не стартует и пустую базу из CSV не заполняет. Политика `restart` поднимает `db` снова; каталог пустой, поэтому init и restore выполняются ещё раз. Достаточно положить дамп на место.

Повторный `docker compose up` дамп не применяет: скрипт инициализации Postgres работает только на пустом volume.

### Дамп с текущей машины

Клиент PostgreSQL 16 (та же major-версия, что образ). Имя базы, пользователь и пароль — из локального `.env`. Файл в git не входит.

```powershell
& "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" -h 127.0.0.1 -p 5432 -U tbilisi -d tbilisi -Fc --no-owner --no-acl -f deploy\tbilisi.dump
```

Перед clone на VPS текущие исходники должны быть на GitHub. Дамп туда не класть: его копируют на сервер отдельно.

### Первый запуск

1. `git clone` репозитория и переход в каталог.
2. `cp .env.example .env`. Заполнить пароль Postgres, `YANDEX_MAPS_API_KEY`, `ADMIN_PASSWORD`, длинный `SESSION_SECRET` и при необходимости `OPENAI_API_KEY`. `DATABASE_URL` в файле можно не менять.
3. Скопировать дамп в `deploy/tbilisi.dump` до первого `up`.
4. `docker compose up --build -d`.

Проверка:

```bash
docker compose ps
docker compose exec db psql -U tbilisi -d tbilisi -c "select count(*) from schools;"
curl -fsS http://127.0.0.1:3000/health
curl -fsS http://127.0.0.1:3000/api/schools
```

Оба сервиса healthy. Число школ и визитов совпадает с локальной базой, не с сидом CSV.

Повторный деплой: `git pull`, затем `docker compose up --build -d`. Volume `pgdata` сохраняется.

Если volume уже инициализировался без дампа и скрипт не смог очистить каталог, восстановление возможно только после `docker compose down -v`. Эта команда удаляет данные Postgres.
